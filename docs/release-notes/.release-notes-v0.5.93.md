# v0.5.93

## Overview

Explicit search providers and managed Tencent Wiki memory projections join safer knowledge authority handling and exact team Run recovery.

**Full Changelog**: https://github.com/catlog22/maestro-flow/compare/v0.5.92...v0.5.93

## Highlights / Features

- `5f844688` — Explicit local/Tencent Atomic/Tencent Wiki search providers across CLI, MCP and Dashboard, including bounded source reads, capability checks and reference-only external results. Existing default search behavior is unchanged.
- `5f844688` — Preview, save, update, remove, status and reconcile for explicitly selected canonical memory projections. Writes are disabled by default and require repository binding, hash checks, explicit acknowledgements and durable operation IDs. Indeterminate writes never automatically retry. Cascade-invalidated projections require reviewed current hashes for recovery.

## Compatibility and Safety

- No actual repository write configuration is enabled by this release. External memory is not canonical authoring or knowledge promotion authority.
- Tencent Wiki has no upstream atomic CAS or idempotency key. Explicit no-CAS/cascade acknowledgement and local receipts do not eliminate external-writer races.
- `--request-id` on knowledge stage/record is a legacy Execution sidecar option, not v3 knowledge idempotency. Remove it and other legacy authority inputs for v3 targets.
- Sealed team Runs remain immutable; follow-up work uses a new receipt-derived locator.
